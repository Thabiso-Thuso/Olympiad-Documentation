Session Log

Scope​

A delivery cycle covering a new anonymous public API, remediation of merge fallout from PR #102, a cross-role navigation alignment, and a documentation pass. All work is verified: tsc --noEmit clean, npm run lint clean, 238/238 Vitest tests passing (39 files), and npm run build succeeding.

Delivered Work​

1. Public API (/api/public/*) — anonymous, read-only​

A new public API surface lets the public website (or any other client) read olympiad data straight from the browser: the school directory, the portal catalogue, the round schedule, published leaderboard marks, and — once a round has closed — its question papers and questions. It is GET-only, requires no credentials, and every response (errors included) carries a wildcard CORS header.

  • src/domain/public-api/queries.ts (new): the shared read queries behind the endpoints, published as a snake_case JSON contract — Dates serialize to ISO-8601 strings, numeric columns are coerced from Drizzle's strings back to JSON numbers, and the results query selects anonymous marks only (no student identities).
  • src/domain/public-api/access.ts (new): the two visibility gates, layered on the existing deriveRoundState — isSemiPublicAvailable (papers/questions readable once the round is closed or released) and areResultsPublished (marks readable only once results_published_at is set).
  • src/app/api/public/_shared.ts (new): publicJson(), which applies the wildcard Access-Control-Allow-Origin: * header to every response.
  • src/app/api/public/schools|portals|rounds/route.ts (new): always-readable directories — schools deduplicated and name-sorted, portals with status and grouped schools, rounds with portal nesting and the qualifying threshold.
  • src/app/api/public/results/route.ts (new): 403 until the organiser publishes; returns { round, portal, results: [{ score }] } ranked highest-first.
  • src/app/api/public/question-papers|questions/route.ts (new): 403 until the round has closed; the questions payload includes correct answers and is safe only because the round can no longer be sat.
  • Shared validation contract: 400 for a missing round_id, 404 for an unknown round, 500 internal (logged server-side).
  • Tests: 40 new tests across 8 suites — tests/api/public/{schools,portals,rounds,results,question-papers,questions}.test.ts (route responses, gates, CORS, failure paths) plus tests/domain/public-api-queries.test.ts and tests/domain/public-api-access.test.ts (query mapping and the gates themselves).

2. Merge fallout remediation (PR #102)​

The merge (dual-PDF AI generation, school-level switcher and hybrid delivery) left several tests and types inconsistent with the behaviour it introduced. All 12 failing tests and 8 TypeScript errors were fixed:

  • tests/components/student/RoundTabs.test.tsx + src/app/(student)/results/[portalId]/RoundTabs.tsx: round fixtures predated the state field the UI now uses to gate results; the component's Round type was completed with state: RoundState and the 'hybrid' delivery method.
  • tests/app/review-page.test.tsx: the review page now looks the round up and refuses to show results unless it is released (one extra mocked query), so every fixture gained a released-round row.
  • vitest.setup.ts: no-op IntersectionObserver stub — jsdom does not implement it and ExamInterface now uses it to track seen questions.
  • tests/app/auth-actions.test.ts, tests/domain/automation-engine.test.ts, tests/app/welcome.page.test.tsx: expected URLs corrected from the removed /educator/dashboard to the canonical /educator?portalId=<id> landing.
  • src/app/educator/rounds/[roundId]/marking/page.tsx: the page awaited params/searchParams but still read them as plain objects (Next 16 Promises); also filtered null questionIds when building initial grades.
  • src/app/organiser/olympiads/[olympiadId]/rounds/[roundId]/ai-actions.ts: the memo URL is now read from question_papers.answerKeyJson.memoUrl (there is no answerKeyUrl column).

3. Cross-role logo navigation alignment​

Audited the top-left logo target for every role. Student, organiser and admin shells already return to /dashboard (admin then redirects to /admin/dashboard); the educator sidebar alone pointed at /educator, so src/app/educator/layout.tsx was updated and all four roles now land on the dashboard hub.

4. Documentation pass​

  • API reference (Technical Documentation/api-documentation.md): new "Part 2: Public API (No Authentication)" — visibility rules per round state, endpoint overview and conventions (snake_case, ISO dates, numeric types), and full coverage of all six endpoints with examples and error contracts; the protection summary gained the public routes; the CORS note was rewritten; later parts were renumbered.
  • Testing documentation (Quality Assurance/testing-documentation.md): public API targets added to the domain and API layers, the suite inventory gained 8 rows, and the round-state vocabulary was corrected (scheduled → open → closed → released).
  • The documentation site builds cleanly (npm run build in Documentation/).

Notes & Follow-ups​

  • Nothing is committed to git yet; all changes are local on the exposing_api branch.
  • The public routes are GET-only with no OPTIONS handler (no CORS preflight support) and no rate limiting — both documented as known characteristics of the surface.
  • Known documentation staleness left in place: the test-suite inventory still lists tests/api/student/sitting.start|save|submit.test.ts, which do not exist in the tree.
  • Optional follow-ups awaiting a decision: making the dashboard hub and welcome page header logos clickable, and re-pointing the educator marking page's "← Return to Dashboard" link to /dashboard if "Dashboard" should always mean the hub.
